1. Day-0 Onboarding Pipeline
Client: Next.js Frontend

User Actions

  • Merchant fills Onboarding Form
  • Submits PAN, GSTIN, and Domain
  • Frontend actively Long-Polls FastAPI for live step-by-step UI updates
Service 1: FastAPI Gateway

Internal Operations

  • Receives HTTP POST /api/merchants
  • Validates payload with Pydantic
  • Returns HTTP 202 Accepted (No timeouts!)
HTTP POST
PUBLISH Q: onboarding_tasks { "merchant_id": "123..." }
INSERT INTO merchants
status='PROCESSING'
Storage: PostgreSQL DB

Table: merchants

  • Stores core profile (PAN, Domain)
  • Stores status (APPROVED, REJECTED)
  • Stores onboarding_steps JSON array for live UI tracking
Broker: RabbitMQ

AMQP Queues

Q1: onboarding_tasks Buffers high-load AI tasks
Q2: notification_events Buffers emails for Node.js
CONSUME onboarding_tasks
Service 2: Celery AI Worker

17-Step Intelligence Pipeline

  1. Calls Govt APIs to validate PAN/GSTIN
  2. Launches Playwright Headless Browser
  3. Crawls Merchant SPA, extracts DOM text
  4. Sends DOM to Groq/Gemini LLM
  5. Identifies prohibited items & policies
  6. Calculates Trust Score (0-100)
  7. Generates Underwriter Memo
External APIs

Network Calls

  • Playwright -> Merchant Website
  • Groq API -> Llama 3 Inference
  • Gemini API -> Flash Inference
  • GSTIN/PAN API -> Verification
UPDATE merchants
SET status='APPROVED'
PUBLISH Q: notification_events { "decision": "APPROVED" }
Service 3: Node.js Notification

Email Dispatcher

  • Listens using amqplib
  • Compiles AI Memo into HTML Template
  • Connects to SMTP via Nodemailer
  • Dispatches Alert to Merchant
CONSUME notification_events
2. Post-Onboarding Recheck Pipeline
Service 1: FastAPI (Scheduler)

APScheduler Cron Jobs

  • Dynamic Rechecks: Background thread runs every 30 mins to sweep the DB for targets (1, 7, 30 days).
  • 48h Grace Period Enforcer: Sweeps DB for merchants where remediation_deadline < NOW() and auto-rejects them.
PUBLISH Q: recheck_tasks { "merchant_id": "987..." }
SELECT id FROM recheck_jobs
WHERE next_run_at < NOW()
Storage: PostgreSQL DB

Tables: snapshots & rechecks

  • Stores Baseline HTML for diffing
  • Stores next_run_at timestamp
  • Records minor policy violations into human_review_cases table
Broker: RabbitMQ

AMQP Queues

Q1: recheck_tasks
Q2: notification_events
CONSUME recheck_tasks
Service 2: AI Worker (Cascade)

4-Tier Math & AI Engine

Halts early at any tier to save compute costs!

T1: Network Ping (Fails on 404/500)
T2: SHA-256 Hash Diff
T3: Semantic Vector Math Cosine Similarity (Distance > 0.2)
Uses Counter Tokens to compute TF-Vectors.
T4: LLM Investigation Crawls site again to find "Bait & Switch"
External APIs

Network Calls

  • httpx -> Network Ping
  • Playwright -> Re-crawling target
  • Groq API -> Context Inference
